* Welcome to My Emacs Configuration

This is a reproducible personal Emacs distribution written as a literate Org
configuration. It is designed for Emacs 29+ and keeps third-party packages as
Git submodules under =site-lisp/extensions/= so the editor, package sources,
and generated configuration can be rebuilt from this repo.

* Philosophy

** Reproducible Personal Distribution
   Treat the configuration as a small personal Emacs distribution: package
   sources are vendored as Git submodules, generated Elisp lives under
   =site-lisp/config/=, and local secrets stay outside git.

** Modular Design
   Configuration is split into logical modules organized by functionality.
   Modules are declared centrally in =config-org/init.org= and loaded through
   the MCG module system.

** Literate Programming
   Written in Org Mode for easy documentation and maintenance

** Performance Optimized
   Startup work is split between immediate, idle, and trigger-based module
   loading to keep the first frame responsive.

* 📦 Installation

   - Emacs 29+ (recommended) or Emacs 28+ with tree-sitter

   - (Optional) Universal Ctags for symbol navigation

** Quick Install

*** Step 1: Clone Repository
    #+begin_src bash
    git clone <repository-url> ~/dotfiles
    cd ~/dotfiles/emacs
    #+end_src

*** Step 2: Initialize Git Submodules
    #+begin_src bash
    make init
    #+end_src

*** Step 3: Generate Configuration
    #+begin_src bash
    make all
    #+end_src

    This creates the ignored local file
    ~site-lisp/config/private/config.el~ for machine-local settings and secrets.

*** Step 4: Customize Local Configuration
    #+begin_src bash
    $EDITOR site-lisp/config/private/config.el
    #+end_src

*** Step 5: Link to Emacs

**** Option A: Symlink (Recommended)
     #+begin_src bash
     # Linux/macOS
     ln -s ~/dotfiles/emacs ~/.emacs.d
     
     # Windows (PowerShell as Administrator)
     New-Item -ItemType SymbolicLink -Path $env:USERPROFILE\.emacs.d -Target D:\config\dotfiles\emacs
     #+end_src

**** Option B: Manual Load
     #+begin_src emacs-lisp
     (load-file "~/dotfiles/emacs/init.el")
     #+end_src

*** Step 6: First Launch
    #+begin_src bash
    emacs
    #+end_src

** Troubleshooting
   #+begin_src bash

** Startup Profiling

Use =make profile-startup= to run a batch startup profile. The report lists
module load times in descending order and highlights key startup entries such

signal for regressions; visual GUI timing still needs manual confirmation.

* 📦 Git Submodule Package Management

This configuration uses Git Submodules to manage third-party Emacs packages. All packages are stored in =site-lisp/extensions/= organized by category.

** Extension Directory Organization

Extensions are organized into category subdirectories:

#+begin_src text
site-lisp/extensions/
├── core/           # Core libraries (dash, s.el, f.el, compat, lazy-load)
├── completion/     # Completion system (vertico, consult, marginalia, orderless, embark)
├── editor/         # Editor features (vundo, hl-todo)
├── git/            # Git integration (magit, with-editor, jujutsu)
├── input/          # Child-frame popups (posframe)
├── lsp/            # LSP and language support (lsp-bridge, web-mode, zig-mode, treesit-auto)
├── org/            # Org-mode extensions (org-modern, ox-hugo, org-download)
├── search/         # Search tools (blink-search, color-rg, consult-todo)
├── snippets/       # Snippet libraries (yasnippet, yasnippet-snippets)
├── ui/             # UI components (dashboard, awesome-tray, holo-layer, pulsar, themes/, nerd-icons)
├── utils/          # Utility packages (auto-save, sort-tab, mwim, json-mode, hydra)
└── docs/           # Documentation tools (markdown-mode, markdown-ts-mode)
#+end_src

** Adding New Packages

To add a new package as a Git submodule:

#+begin_src bash
# Syntax: make gsa URL=<repo-url> CAT=<category> NAME=<package-name>

# Example: Add a new theme package
make gsa URL=https://github.com/hlissner/emacs-doom-themes CAT=ui/themes NAME=doom-themes

# Example: Add a new editor package
make gsa URL=https://github.com/abo-abo/swiper CAT=editor NAME=swiper

# Example: Add a new LSP language support
make gsa URL=https://github.com/emacs-lsp/lsp-mode CAT=lsp NAME=lsp-mode
#+end_src

After adding a package:
1. The submodule is added to =.gitmodules=
2. The package is cloned to =site-lisp/extensions/<CAT>/<NAME>=
3. Commit the changes: =git add .gitmodules site-lisp/extensions/<CAT>/<NAME> && git commit=

** Updating Packages

To update all packages to their latest versions:

#+begin_src bash
# Update all submodules
make gsu

# Or use the alias
make up
#+end_src

For a complete sync (recommended after cloning or when submodules are out of sync):

#+begin_src bash
# Full sync: initialize + switch to main branch + pull latest
make gss
#+end_src

** Removing Packages

To remove a package:

#+begin_src bash
# Syntax: make gsrm CAT=<category> NAME=<package-name>

# Example: Remove a package
make gsrm CAT=ui/themes NAME=doom-themes
#+end_src

This will:
1. Deinitialize the submodule
2. Remove it from the Git index
3. Clean up the =.git/modules= directory

** Checking Package Status

#+begin_src bash
# View status of all submodules
make gsst

# Or use the alias
make st
#+end_src

** Best Practices

1. *Choose the right category*: Place packages in appropriate category directories
2. *Use descriptive names*: Package names should match the repository name
3. *Commit after changes*: Always commit =.gitmodules= and the submodule directory together
4. *Regular updates*: Run =make gsu= periodically to keep packages updated
5. *Test after updates*: Run =make test= after updating to catch any breaking changes

* ⚡ Performance Optimization

** Module Loading Strategy

The configuration uses a three-tier loading strategy so the default =*scratch*=
buffer can appear early while heavier or on-demand tools finish loading later:

| Loading Type | When Loaded | Modules |
|--------------+-------------+---------|
| Immediate    | At startup  | first-frame essentials: font, ef-themes, nerd-icons, pulsar, editor defaults, minibuffer basics, project/diagnostics basics |
| Idle         | After 2s idle | visual chrome and heavy/on-demand tools: awesome-tray, holo-layer, vundo, yasnippet, compile, blink-search, dirvish, org, magit, clutch, lsp-bridge, color-rg, majutsu, vale |
| Deferred     | On demand   | trigger-backed language and writing modules such as python, zig, web, and markdown |

Some idle modules expose lightweight lazy command entries before the module is
loaded. The command keys are available immediately, but the backing module is
loaded on first use. This keeps startup fast while avoiding an early keybinding
gap for compile, magit, vundo, blink-search, color-rg, dirvish, org capture,
clutch, and majutsu.

Two idle choices are intentional:

- =awesome-tray= replaces the mode-line, so loading it after the first scratch
  frame keeps startup from visibly redrawing.
- =org= is one of the heaviest Windows startup modules, so agenda/capture
  support is loaded after the first frame unless you change its =:load= metadata.

Use =make profile-startup= when changing this list. It prints module timings and
the current idle queue without mixing third-party warnings into the report.

** Idle Loading Configuration

Non-essential modules are loaded during idle time to speed up startup. The
default strategy lives next to each module declaration in =config-org/init.org=:

#+begin_src emacs-lisp
(mcg!
 :tools
 (magit :load idle)
 :lang
 (python :load deferred))
#+end_src

Use =immediate= for startup modules, =idle= for first-frame-safe background
loading, and =deferred= for trigger-backed file modes. The idle delay remains
configurable from =site-lisp/config/private/config.el=:

#+begin_src emacs-lisp
;; Configure idle loading delay (default: 2 seconds)
(setq mcg-idle-load-delay 2)

;; Add modules to idle loading:
(mcg-add-idle-load-module :completion 'vertico)
(mcg-add-idle-load-category :enhance)  ; Add entire category
#+end_src

** Deferred Loading

Language and writing modules are loaded on-demand when you open a matching
file. Markdown is deferred so ordinary startup does not pay for Markdown mode.
Vale is optional: the module is idle-loaded, and diagnostics only run when you
change the default =mcg-vale-enable nil= to =(setq mcg-vale-enable t)= in
=site-lisp/config/private/config.el=.

| File Extension | Module Loaded |
|----------------+---------------|
| =.py=          | python        |
| =.zig=         | zig           |
| =.html=, =.css=, =.js=, =.ts=, =.tsx=, =.vue= | web |
| =.md=          | markdown      |

* 🔑 Keybinding Registry

The configuration uses a centralized keybinding registry system for conflict detection and documentation.

** Using the Registry

#+begin_src emacs-lisp
;; Register a keybinding (instead of global-set-key)
(mcg-bind-key "C-c s l" consult-line "init-keybindings")

;; With optional keymap
(mcg-bind-key "C-c C-b" eval-buffer "init-keybindings" emacs-lisp-mode-map)
#+end_src

** Conflict Detection

When a keybinding conflict is detected, a warning is displayed:

#+begin_example
Warning: Keybinding conflict: C-c s l
  Was: old-command (from module-a)
  Now: new-command (from module-b)
#+end_example

** Query Keybindings

** Org Configuration Surface

Core storage is controlled by =mcg-org-directory=,
=mcg-org-agenda-directory=, and =mcg-org-notes-directory=. Agenda behavior is
configured through =mcg-org-agenda-files= and =mcg-org-agenda-custom-commands=.

Babel is conservative by default: =mcg-org-babel-confirm-evaluate= is enabled,
=mcg-org-export-babel-evaluate= is disabled, and Zig support is controlled by
=mcg-org-babel-enable-zig=. Source block prompts use
=mcg-org-babel-src-block-languages=. Default Babel languages are
=emacs-lisp=, =shell=, =python=, =js=, =css=, and =org=; enable =C=, =dot=,
=plantuml=, or =sql= from private config only when a project needs them.

Hugo capture and export are opt-in. The default is =mcg-org-hugo-enable nil=;
set =(setq mcg-org-hugo-enable t)= in =site-lisp/config/private/config.el= to
load easy-hugo, ox-hugo, and the =h=/=hb= capture templates. Related knobs are
=mcg-blog-base-directory=, =mcg-org-hugo-postdir=, and
=mcg-org-blog-capture-directory=. The current capture surface creates a
one-file-per-post =hb= template instead of topic-specific shortcuts.
