* 欢迎使用我的 Emacs 配置

这是一个可复现的个人 Emacs 发行版，使用 Org Mode 文学编程编写。
它面向 Emacs 29+，把第三方包以 Git 子模块形式放在 =site-lisp/extensions/=
下，使编辑器配置、包源码和生成后的 Elisp 都能从本仓库重建。

* 设计理念

** 可复现的个人发行版
   将本配置视为一个小型个人 Emacs 发行版：包源码由 Git 子模块托管，
   生成后的 Elisp 位于 =site-lisp/config/=，本机密钥和密码留在 git 之外。

** 模块化设计
   配置按功能拆分为逻辑模块。模块在 =config-org/init.org= 中集中声明，
   并由 MCG 模块系统负责加载。

** 文学编程
   使用 Org Mode 编写，便于文档化和维护

** 性能优化
   启动工作被拆分为立即加载、空闲加载和按触发器加载，以保持首帧响应速度。

* 🎯 功能特性

** 核心技术栈
   - Emacs 29+ 支持 tree-sitter
   - LSP Bridge 语言服务器集成
   - Vertico + Marginalia + Embark 补全系统
   - Magit Git 操作

** 语言支持
   完整的开发支持：
   - *系统编程*: Zig，包含 build/test/run 辅助命令
   - *Web 开发*: TypeScript, JavaScript, HTML/CSS, JSX/React, Vue
   - *动态语言*: Python，包含 pytest 和 Ruff 辅助命令
   - *标记语言*: Markdown, Org Mode

** 主要功能
   - [[https://github.com/minad/vertico][Vertico]]: 现代化补全
   - [[https://github.com/minad/marginalia][Marginalia]]: 丰富注解

* 📦 安装

** 前置要求
   - Emacs 29+（推荐）或 Emacs 28+ 配合 tree-sitter
   - Git 用于包管理
   - Node.js 用于 lsp-bridge
   - （可选）Universal Ctags 用于符号导航

** 快速安装

*** 步骤 1: 克隆仓库
    #+begin_src bash
    git clone <repository-url> ~/dotfiles
    cd ~/dotfiles/emacs
    #+end_src

*** 步骤 2: 初始化 Git 子模块
    #+begin_src bash
    make init
    #+end_src

*** 步骤 3: 生成配置
    #+begin_src bash
    make all
    #+end_src

    这会创建被 git 忽略的本地配置文件
    ~site-lisp/config/private/config.el~，用于机器本地配置、密钥、token 和密码。

*** 步骤 4: 定制本地配置
    #+begin_src bash
    $EDITOR site-lisp/config/private/config.el
    #+end_src

*** 步骤 5: 链接到 Emacs

**** 方式 A: 符号链接（推荐）
     #+begin_src bash
     # Linux/macOS
     ln -s ~/dotfiles/emacs ~/.emacs.d
     
     # Windows (以管理员身份运行 PowerShell)
     New-Item -ItemType SymbolicLink -Path $env:USERPROFILE\.emacs.d -Target D:\config\dotfiles\emacs
     #+end_src

**** 方式 B: 手动加载
     #+begin_src emacs-lisp
     (load-file "~/dotfiles/emacs/init.el")
     #+end_src

*** 步骤 6: 首次启动
    #+begin_src bash
    emacs
    #+end_src

** 故障排除
   #+begin_src bash
   make st        # 检查包状态
   make clean     # 清理生成文件
   make all       # 重新生成配置
   make h         # 查看所有命令

** 添加新包

将新包添加为 Git 子模块：

#+begin_src bash
# 语法: make gsa URL=<仓库地址> CAT=<类别> NAME=<包名>

# 示例：添加新主题包
make gsa URL=https://github.com/hlissner/emacs-doom-themes CAT=ui/themes NAME=doom-themes

# 示例：添加新编辑器包
make gsa URL=https://github.com/abo-abo/swiper CAT=editor NAME=swiper

# 示例：添加新 LSP 语言支持
make gsa URL=https://github.com/emacs-lsp/lsp-mode CAT=lsp NAME=lsp-mode
#+end_src

添加包后：
1. 子模块被添加到 =.gitmodules=
2. 包被克隆到 =site-lisp/extensions/<CAT>/<NAME>=
3. 提交更改：=git add .gitmodules site-lisp/extensions/<CAT>/<NAME> && git commit=

** 更新包

更新所有包到最新版本：

#+begin_src bash
# 更新所有子模块

# 或使用别名

#+end_src

完整同步（推荐在克隆后或子模块不同步时使用）：

#+begin_src bash
# 完整同步：初始化 + 切换到主分支 + 拉取最新
make gss
#+end_src

** 移除包

移除一个包：

#+begin_src bash
# 语法: make gsrm CAT=<类别> NAME=<包名>

# 示例：移除一个包
make gsrm CAT=ui/themes NAME=doom-themes
#+end_src

这将：
1. 取消初始化子模块
2. 从 Git 索引中移除
3. 清理 =.git/modules= 目录

#+begin_src bash
# 查看所有子模块状态

# 或使用别名
make st
#+end_src

** 最佳实践

1. *选择正确的类别*：将包放在适当的类别目录中
2. *使用描述性名称*：包名应与仓库名匹配
3. *更改后提交*：始终一起提交 =.gitmodules= 和子模块目录
4. *定期更新*：定期运行 =make gsu= 保持包更新
5. *更新后测试*：更新后运行 =make test= 捕获任何破坏性更改

* ⚡ 性能优化

** 模块加载策略

本配置使用三层加载策略，让默认 =*scratch*= buffer 尽早出现，同时把较重或按需工具放到
首屏之后：

| 加载类型 | 加载时机 | 模块 |
|----------+----------+------|
| Immediate | 启动时 | 首屏必需项：font、ef-themes、nerd-icons、pulsar、编辑默认值、minibuffer 基础、project/diagnostics 基础 |
| Idle | 空闲 2 秒后 | 视觉外壳和重/按需工具：awesome-tray、holo-layer、vundo、yasnippet、compile、blink-search、dirvish、org、magit、clutch、lsp-bridge、color-rg、majutsu、vale |
| Deferred | 按需触发 | 有文件类型触发器的语言与写作模块，例如 python、zig、web 和 markdown |

部分 idle 模块会在模块加载前暴露轻量 lazy command entry。按键入口启动后立即可用，
但背后的模块会在首次调用时加载。这样既保留启动速度，也避免 compile、magit、vundo、
blink-search、color-rg、dirvish、org capture、clutch、majutsu 这些高频入口在启动初期出现按键空窗。

其中两个 idle 决策是刻意保留的：

- =awesome-tray= 会替换 mode-line，放到首个 scratch frame 之后加载可以避免启动时明显重绘。
- =org= 是 Windows 启动期最重的模块之一，所以 agenda/capture 支持默认放到首帧之后加载；需要时可以调整它的 =:load= 元数据。

调整加载策略后，建议运行 =make profile-startup=。它会输出模块耗时和当前 idle
队列，并且不会把第三方 warning 混入报告。

** Idle 加载配置

非首屏必需模块通过 idle 加载加快启动。默认策略直接写在 =config-org/init.org=
的模块声明旁边：

#+begin_src emacs-lisp
(mcg!
 :tools
 (magit :load idle)
 :lang
 (python :load deferred))
#+end_src

=immediate= 表示启动加载，=idle= 表示首帧之后空闲加载，=deferred= 表示按文件触发。
idle 延迟仍可在 =site-lisp/config/private/config.el= 中配置：

#+begin_src emacs-lisp
;; 配置 idle 加载延迟（默认：2 秒）
(setq mcg-idle-load-delay 2)

;; 添加单个模块或整个类别到 idle 加载
(mcg-add-idle-load-module :completion 'vertico)
(mcg-add-idle-load-category :enhance)
#+end_src

** Deferred 加载

语言和写作模块在打开匹配文件时按需加载。Markdown 按需加载，所以普通启动
不会提前付出 Markdown mode 的成本。Vale 默认关闭：模块会在 idle 阶段加载，
但只有在 =site-lisp/config/private/config.el= 中把 =mcg-vale-enable nil=
改为 =(setq mcg-vale-enable t)= 后才运行文稿诊断。

| 文件扩展名 | 加载模块 |
|------------+----------|
| =.py=      | python   |
| =.zig=     | zig      |
| =.html=, =.css=, =.js=, =.ts=, =.tsx=, =.vue= | web |
| =.md=      | markdown |

* 📝 Org Mode

=:org org= 模块会加载 Org 核心，以及 agenda、capture、Babel、视觉增强、
图片插入和可选 Hugo 发布相关子模块。

** 用户命令

| 命令                             | 描述                        |
|----------------------------------+-----------------------------|
| =M-x mcg-org-initialize-directories= | 创建当前配置的 Org 目录     |
| =M-x mcg/org-open-notes=         | 打开 =mcg-org-notes-directory= |
| =M-x mcg/org-open-agenda-dir=    | 打开 =mcg-org-agenda-directory= |

** Org 快捷键

| 快捷键        | 描述                         |
|---------------+------------------------------|
| C-c n c       | Capture 笔记/任务/模板       |
| C-c n a       | 打开 agenda                  |
| C-c n l       | 保存 Org 链接                |
| C-c n t       | 显示 TODO 列表               |
| C-c n v       | 通过 org-download 插入剪贴板图片 |
| C-c C-v C-b   | 执行当前 buffer 所有 Babel 代码块 |
| C-c C-v C-r   | 删除所有 Babel 执行结果      |
| C-c C-v i     | 插入源码块                   |

** Org 配置面

核心存储目录由 =mcg-org-directory=、=mcg-org-agenda-directory= 和
=mcg-org-notes-directory= 控制。Agenda 使用 =mcg-org-agenda-files= 和
=mcg-org-agenda-custom-commands= 配置文件范围与自定义视图。

Babel 默认偏保守：=mcg-org-babel-confirm-evaluate= 开启，
=mcg-org-export-babel-evaluate= 关闭；Zig 支持由
=mcg-org-babel-enable-zig= 控制，插入源码块的候选语言来自
=mcg-org-babel-src-block-languages=。默认 Babel 语言是 =emacs-lisp=、
=shell=、=python=、=js=、=css= 和 =org=；=C=、=dot=、=plantuml=、=sql=
这类扩展语言只在项目需要时从 private 配置启用。

Hugo capture/export 默认关闭：默认值是 =mcg-org-hugo-enable nil=。需要时在
=site-lisp/config/private/config.el= 中设置 =(setq mcg-org-hugo-enable t)=，
才会加载 easy-hugo、ox-hugo 以及 =h=/=hb= capture 模板。相关配置包括
=mcg-blog-base-directory=、=mcg-org-hugo-postdir= 和
=mcg-org-blog-capture-directory=。当前 capture 入口提供一类 one-file-per-post
的 =hb= 模板，而不是按主题拆分多个快捷模板。

* 🔍 调试

** 常见错误

*** 扩展加载错误
#+begin_src bash
# 初始化所有子模块
make init
#+end_src

*** 循环依赖
#+begin_src emacs-lisp
M-x mcg-check-circular-dependencies
#+end_src

*** 诊断命令
#+begin_src emacs-lisp
M-x mcg-doctor       ; 检查配置、Development Environments、Tree-sitter Grammars
M-x mcg-list-modules ; 查看模块状态
M-x mcg/show-logs    ; 查看近期日志
#+end_src

=M-x mcg-doctor= 会检查路径、核心模块、扩展、外部开发工具、Python/Web/Zig
的 Development Environments，以及当前语言/写作模块需要的 Tree-sitter
Grammars。环境部分会显示 =uv.lock=、=poetry.lock=、=pdm.lock=、=build.zig=、
Antfu ESLint 等项目线索，并报告 Emacs 当前会优先使用的 formatter/test/build
命令。

Python 命令默认会优先使用项目本地 runner。开启
=mcg-python-detect-project-tools= 时，包含 =uv.lock=、=poetry.lock= 或
=pdm.lock= 的项目会分别使用 =uv run=、=poetry run= 或 =pdm run= 执行
pytest/Ruff；否则回落到 =mcg-python-test-command= 和
=mcg-python-ruff-command=。
